## AirDrop：发射后端换成 `NL80211_CMD_FRAME`，打通"与 Wi-Fi 共存"

### 结论先行
- 监视接口注入这条路在**固件层**就是死的（0040：固定断言），不是补丁能修的。
- 唯一可用的发射通道是 cfg80211 的 `NL80211_CMD_FRAME`（WMI `MGMT_TX`），
  **不需要 con_mode=4**，所以 STA 可以一直保持关联 → AirDrop 与普通 Wi-Fi 共存。
- 硬约束：**没有关联就没有 RX**。监视 vdev 打开返回 `-107`（ENOTCONN，
  `__hdd_mon_open`），ROC 返回 `-22`（EINVAL）。两条独立证据。

### 代码改动（filin-rs）
- `os::nl80211::MgmtTx`：CMD_FRAME(59)/IFINDEX(3)/WIPHY_FREQ(38)/FRAME(51)/
  DONT_WAIT_FOR_ACK(142)。常量抄 `tools/awdl-mgmt-tx.c`。
- `request_frame()` 按 `nlmsg_seq` 匹配 ack，跳过 genl reply 和 MLME 事件；
  只 recv 一次会让后续请求全部错位。
- `runtime::Injector{Packet,MgmtTx}`；上层继续产出 radiotap 帧，
  MgmtTx 分支用 `strip_radiotap()` 剥前缀。
- `FILIN_TX_IFACE=<iface>` 打开共存模式：跳过 `set_monitor`/`set_channel`。
- **关键坑**：`self_addr` 必须取发送 vdev 的 MAC（wlan0），取监视接口的会让
  cfg80211 整帧拒绝（addr2 != 发送接口）。改之前 0 成功，改之后 8 秒 192 帧 0 失败。

### radio.sh 重写
- 删掉 SHA256 哈希闸门（对"volatile 加载"是假阴性，对截断文件是假阳性）。
- 删掉 600 秒上限（会在常驻第 10 分钟杀掉电台）。
- 流程：能力检查 → 未关联则 exit 7 明确提示 → 建 awdlmon → capture_hold=1
  → `FILIN_TX_IFACE=wlan0` 启动 filin → 看到 `transmitting via NL80211_CMD_FRAME`
  写 listening → 守护到 stop/应用退出 → 还原（hold=0、删 awdlmon）。

### 应用层
- 修 `AirDropService.runSession` 的 finally 覆盖 bug：`onIdle` 会把
  `onError` 的具体原因盖成"会话结束"。加 `failed` 标志。
- 清掉所有"恢复 Wi-Fi / 独占 Wi-Fi"的过时文案（不再关 Wi-Fi）。
- `AirDropResidentService.status()`：phase=ERROR 时显示真实原因，不再说"正在启动"。

### 验证
- 设备上跑测试：`filin_rs 247 passed`（新增 5）、`awdl_emit 6 passed`；
  Kotlin `AirDropEventsTest 10 passed`。
- 实机：8 秒 192 帧，PSF 352 / MIF 942 字节，与 C 工具 plan 同尺寸；
  发完 `con_mode=0`、wlan0 仍 managed、wifi_on=1。
- UI 截图确认：待机状态与限时会话都显示"请先连接一个 Wi-Fi 网络"。

### 仍未证明
- 空口（周围 0 BSS，无法关联 → 无法起监视接口）。
- filin 不做 ROC：收发会不同频，有 AP 后需要在每个可用窗口前
  `REMAIN_ON_CHANNEL`(55)。

记录：ROADMAP §20。

## 续 2：发射侧围剿完毕，结论是「还不能用」

### 又一个回归：`--no-force-master` 让 mDNS 一封都没发
- `rebroadcast=0 spread=0`（整个会话）。闸门是
  `can_send_in(sync, now, MULTICAST_GUARD_TU)`，采纳真实 master 后从未放行。

- **所以 radio.sh 保留 force-master**（更正确的选项当前不可用，见 ROADMAP §23.1）。

### 帧类型：mDNS 是 802.11 数据帧（type 2），走管理帧通道
- `build_data_frame` 写 `0x0008`。补丁 0043 放宽了
  `cfg80211_mlme_mgmt_tx` 的「只准管理帧」，条件是
  **station 接口 + 数据帧 + 精确前缀 `aa aa 03 00 17 f2 08 00`**。
- 前缀已有单测覆盖，把「为什么」写进注释（前缀一改，驱动静默丢所有数据帧）。

### ROC 在 STA 上完全不可用（新否定结果）
```
iw dev wlan0 roc start 5260 5000  → -22
iw dev wlan0 roc start 2412 3000  → -22
iw dev wlan0 offchannel 5260 5000 → -22
```
关联状态下同信道/异信道都拒。0044 唯一那次空口证明的条件是
「during a remain-on-channel」，所以「固件是否真把帧打出去」**未证明**。

### 抓包（50 287 帧）：没有任何对端把我们当对端

未解决：固件是否真发出（无 ROC 无法验证）、Mac 不认我们、

## AirDrop：补丁上下文返工 + .ko 链接配方（同日第五段）

**两个补丁的 hunk 上下文过期，导致 GNU patch 静默错位，这是前两次构建失败的真因。**

1. **0036（monitor-netdev-tx-queue）**：默认 fuzz=2 把整块代码搬进了
   `hdd_open_cesium_nl_sock(void)`（无 `adapter` 形参）→
   `use of undeclared identifier 'adapter'`。正确落点是 `__hdd_mon_open()`
   内 `netif_carrier_on(dev);` 之后。
   返工方法：用 Python 构造 post-image（0035 先 `patch --fuzz=0` 应用），
   `git diff --no-index` 生成新 hunk。**关键教训：0036 的 pre-image 必须是
   已应用 0035 之后的树**，否则 hunk 的 old-image（6 行连续上下文）在
   post-0035 文件里不存在（0035 的插入正好落在那 6 行中间），Plan A 必然失败。
   hunk 行号不用改——0035 插在 hunk 首个上下文行之后，行号不变。
   已加 `--fuzz=0` 到构建脚本，并加了三段式 patch audit（块存在 / 在
   `__hdd_mon_open` 内 / 没漏进 `hdd_open_cesium_nl_sock`）。

2. **0041（awdl-tx-drop-tracing）**：hunk2（`uint32_t drop_site;` 声明）上下文
   指望 `unsigned int bytes;` 后面有 `uint8_t tx_vdev_id;`，但 0040 已把这个
   变量删掉（改成直接用 `adapter->vdev_id`）→ 只有声明 hunk 失败、使用 hunk
   成功，半应用状态。返工同上：pre = pristine + 0001..0040，post = 当前树 +
   手工补回声明。

3. **0045（capture-hold）单 hunk 失败但无害**：0046 已把 bounded capture slot
   整套删掉，0045 是给它打补丁；树里没有任何符号引用
   `marionette_awdl_capture_hold`。已在构建脚本中标为 superseded by 0046 跳过。

4. **`.ko` 链接配方（此前一直没找到，本轮补上）**：
   `build-baseline.sh` 默认只出 `kiwi_v2.o`，不出 `.ko`。要 `.ko` 必须：
   ```
   export DRIVER_TARGET=modules
   export DRIVER_PROVIDER_SYMVERS=<stock-provider.symvers>
   export DRIVER_JOBS=8
   bash build-baseline.sh <kernel> <kernel-out> <wlan> <clang>
   ```
   provider symvers 在 `build/airdrop/driver/refs/stock-provider.symvers`
   （7891 条导出，由 `driver/stock-symvers.py` 从原厂 ELF 模块恢复）。
   链接产物约 520 MB，需 `llvm-strip --strip-debug` 才降到约 24 MB。
   `CONFIG_DEBUG_INFO_BTF_MODULES=y` 已满足；模块 `.BTF` 仍缺（无 vmlinux）。

5. **`git clean -qfd` 不清 gitignored 的 `.o`**：增量构建只重编被 patch 改过的
   文件，这是构建只有几行 CC 输出的原因，不是构建没跑。
