## 0027 / 0035 / 0036 — monitor netdev TX 队列 DRV_XOFF 根因与修复（进行中）

### 已确立的失败链（候选 0035，raw_tx=Y，awdlmon ifindex 40）

- 0034：帧死在 `noop_enqueue()`（`ndo_start_xmit` 从未进入）。
  证据：`skb:kfree_skb` 栈 `__dev_xmit_skb → __dev_queue_xmit → dev_queue_xmit → packet_snd`。
  根因：monitor netdev NO-CARRIER → `dev_activate()` 在
  `if (!netif_carrier_ok(dev)) return;` 早退，从未 `transition_one_qdisc()`，
  `txq->qdisc == &noop_qdisc`。
- 0035 修掉 noop_qdisc 后，帧进 mq qdisc 但仍不到驱动：
  `qdisc_dequeue: txq_state=0x1 packets=0 skbaddr=0x0`，
  `sch_direct_xmit()` 走 `dev_requeue_skb()`，backlog 只增不减。

### 0036 根因（本次源码审计闭合）

`txq_state 0x1` = `__QUEUE_STATE_DRV_XOFF`（`enum netdev_queue_state_t` 第 0 位）。
驱动里只有 4 个 `netif_tx_stop_all_queues()` 调用点，全在
`wlan_hdd_netif_queue_control()`（`wlan_hdd_tx_rx.c:1187/1342`）。

`hdd_open_adapter()` 的 `QDF_MONITOR_MODE` case 落到 station-adapter 创建分支，
结尾必然执行 `wlan_hdd_netif_queue_control(adapter,
WLAN_STOP_ALL_NETIF_QUEUE_N_CARRIER, WLAN_CONTROL_PATH)`（main.c:7490/7542）。
netdev 创建时是 DOWN，`__hdd_mon_open()` 不跑，`pause_map` 的
`WLAN_CONTROL_PATH` 位无人清除；`__hdd_mon_open()` 也完全没有
start-queues 调用（对比 `__hdd_open()` main.c:4640 的 "Enable Tx Queues only
when we are connected"）。
`transition_one_qdisc()` 不清 netdev_queue state 位 → DRV_XOFF 跨 up 存活。

**修复**：`__hdd_mon_open()` 尾部把 0035 的 `netif_carrier_on(dev)` 换成
`wlan_hdd_netif_queue_control(adapter, WLAN_START_ALL_NETIF_QUEUE_N_CARRIER,
WLAN_CONTROL_PATH)` —— 与创建时的 stop 完全对称（`WLAN_CONTROL_PATH = 1`，
`cdp_txrx_mob_def.h`）。

### kprobe 陷阱（重要，别重复踩）

- mksh 的内建 `echo` **不报告写错误**，写 `kprobe_events` 被内核拒也 rc=0、
  无 stderr。必须用 `printf ... | tee -a kprobe_events` 才能看到。
- 本机一次只允许注册**一个** kprobe；失败时要先 disable+remove（`--`）再注册。
- **LTO_CLANG_FULL 下模块函数的 kprobe 可能落在死的外联副本上**
  （本例：`wlan_hdd_netif_queue_control` 的 kprobe 全程 0 hit，
  但 `hdd_stop_no_trans` 的 kprobe 命中 1 次而它必然调用前者）。
  → 模块内符号的 kprobe "0 hits" 不能当证据。核心内核符号
  （`dev_hard_start_xmit` / `noop_enqueue` / sch_generic 系列）可靠。
- 验收要用模块参数 `marionette_awdl_submitted` / `..._rejected`，不用 kprobe。

## 0038 / 0039：固件侧证据闭环，S2 主机侧完结

补上欠账：`0038-monitor-exception-frame-contract.patch`、

**新证据来源（重要）**：RDDM 时固件把 SFR 字符串交给 MHI，主机打进 kmsg：

```
mhi mhi_1107_00.01.00: [E][mhi_process_sfr] cmnos_thread_patch.c:1170:0x8Asserted in:0x18dc754:0x1801164, line#2834
```

0037（vdev-based TCL MSDU）、0038（+SEND_AS_STANDALONE exception 契约）、
0039（+完整 htt_tx_msdu_desc_ext2_t TX 参数）三次给出**逐字节相同**的 SFR 与 PC。

**外部参照（决定性的负面结论）**：QCACLD-2 官方注入提交
Codeaurora 3d3ad787 `qcacld-2.0: Add packet injection in monitor mode`
只支持 `CONFIG_HL_SUPPORT`，且让**固件自己解析 radiotap 头**取 rate/retries；
QCACLD-3 这棵树 TX 侧没有该机制，不能照搬。kimocoder/
qualcomm_android_monitor_mode 也确认 QCACLD-3 注入只在个别 CAF 分支出现过。
OWL/opendrop 官方要求外接 Atheros 类网卡——Qualcomm 内部芯片做 AWDL TX 是无人区。

**写代码时踩到的两个坑**：
- `htt.h` 的 `learning_frame` 位置位 = "固件丢弃该帧不进 TQM"，与注入相反。
- `host_tx_desc_pool` 是 TQM-BYPASS 的强制项（`dp_tx_prepare_desc_single()`
  的 `#if !TQM_BYPASS_WAR` 分支必然开 bypass），不置就是违约。
- `CDP_INVALID_PEER`=0xffff 与 `DP_INVALID_PEER`=0xFFFE 不相等，所以
  `dp_tx_send_msdu_single()` 里既不走 HOST_INSPECTED 也不走 PEER_BASED，
  落在干净的 `vdev->htt_tcl_metadata` 分支 —— TCL 元数据本来就是对的。

**结论**：S2 主机侧无已知缺口，固件为结构性拒绝。后续是架构决策
（P2P/GO vdev 承载 AWDL 数据 / USB 外接网卡），见 ROADMAP.md §6.7。
